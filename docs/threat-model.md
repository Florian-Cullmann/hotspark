# Focused threat review (0.4, early stage)

The supported operator is trusted and deploys reviewed code. Docker is not a VM security boundary or a perfect hostile-code sandbox. Do not provide anonymous public build access or market this as hardened hostile multi-tenancy.

| Threat                                       | Practical protection                                                                                                                                  | Remaining risk                                                                                                                                               |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Stolen token/admin session                   | Secure random token digests, scopes, expiration, revocation, eight-hour login sessions, server-side logout, rate limits                               | Admin tokens control all projects and privileged operations; project RBAC/2FA absent                                                                         |
| Compromised browser                          | In-memory bearer token, no persistent browser token/cookie, same-origin API                                                                           | XSS can act as admin; no protection from a compromised browser                                                                                               |
| CSRF/cookies                                 | API requires explicit Authorization header; no authentication cookies or cross-origin credential support                                              | Any future cookie login must add secure/HttpOnly/SameSite settings and explicit CSRF design                                                                  |
| Malicious Git/Dockerfile/package scripts     | Exact commits, isolated temporary checkout, bounded source context/time, no runtime secrets in build inputs                                           | BuildKit has shared CPU/memory/PID ceilings, but executes arbitrary code with egress; per-build fairness, egress controls and VM isolation remain incomplete |
| Container escape / Docker / agent compromise | No workload socket, host mounts/network/privileged mode; non-root/cap-drop/NNP/resource limits                                                        | Root agent and Docker daemon are host-root equivalent; host kernel shared                                                                                    |
| SSRF                                         | Public GitHub source restriction; typed agent operations; webhook public IPv4 validation with DNS pinning/no redirects; update origin root-configured | Hosted code can reach network/host services; shared proxy bridge allows exposed containers to communicate                                                    |
| Command injection / traversal                | Fixed host executables and argv; UUID paths; no shell API; source symlink validation; update checksum boundary                                        | Trusted release archives/scripts are executable root-level code; publisher compromise is critical                                                            |
| Secret leakage / image layers                | AES-GCM vaults, tmpfs delivery, no runtime secrets as build args, bounded/redacted logs, owner-only CLI files                                         | Committed secrets and arbitrary source assets may enter layers; root and applications can read their own secrets; backups are unencrypted                    |
| Domain conflicts                             | Canonical hostname validation, database uniqueness, serialized intent, deterministic routing                                                          | Domain ownership verification and certificate automation edge cases remain                                                                                   |
| Poisoned webhooks                            | HMAC timestamp signature, no arbitrary response execution, bounded retries/payloads, SSRF restrictions                                                | Receiver must verify signature/replay window and idempotency; adapter not a guaranteed delivery service                                                      |
| Disk exhaustion / resource abuse             | CPU/memory/PID runtime defaults, bounded logs/source workspaces, disk warnings, explicit owned-image GC                                               | No storage quotas, backup-size quota or hostile-tenant defense; shared build ceilings do not reserve host capacity; metadata/backups require archival        |
| Update/recovery failure                      | Immutable versions, checksum/compatibility gate, validated DB backup, health checks, retained old version, persistent journal                         | Metadata/filesystem/DB are not one power-loss transaction; migration compatibility depends on reviewed releases                                              |

Audit trails cover mutations, operational completion, token creation/revocation and login/logout. They are neither tamper-proof nor complete request-forensics. Normal errors do not return raw Docker/database output. Notifications and metrics intentionally omit credentials and workload logs.

Priorities before a broader threat model: isolated builder hosts/VMs, explicit egress policy, project authorization, signing/provenance and SBOM, key rotation and encrypted off-host restore drills, quotas and administrative 2FA. A migration to cookies or remote agents requires its own security review.
