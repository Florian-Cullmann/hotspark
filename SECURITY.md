# Security policy

Hotspark is experimental and has no production support or security-response SLA. Only the current development version is reviewed; released versions must be evaluated before production use. Docker is not a VM or hostile-code security boundary.

When hosted publicly on GitHub, enable private vulnerability reporting and submit suspected vulnerabilities through the repository's Security tab. If private reporting is unavailable, ask a maintainer for a private reporting channel without disclosing exploit details in a public issue. This repository does not invent a maintainer email or promise a response deadline.

Include affected version, prerequisites, reproduction steps and impact. Do not include live credentials, user data or details from systems you do not own. Review docs/security-model.md and docs/threat-model.md for supported trust assumptions and known limitations.
